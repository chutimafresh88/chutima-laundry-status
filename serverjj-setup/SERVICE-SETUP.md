# Chutima SERVERJJ connection service setup

Use only after the dedicated Chutima database setup completes on SERVERJJ. The service installer opens a Windows UI and waits for the install button. It requires Administrator and reads only the Chutima database connection generated by that setup; no passwords or shop data are included in this repository.

It downloads SHA-256 pinned Node.js 24.19.0 and WinSW 2.12.0 from their official sources into C:\\ChutimaServer, installs the ChutimaServer service under LocalService with its own service SID, and grants access to dedicated Chutima paths. It creates shop-specific TLS certificates and a private pairing file under E:\\ChutimaData\\Pairing. The sole new firewall rule permits the dedicated Node executable on TCP 8443 from LocalSubnet. It does not alter SML, other services, global PATH, or the Windows certificate store. It starts after ChutimaPostgreSQL and backs up the Chutima database hourly to E:\\ChutimaData\\Backups-Chutima.

This is an installation checkpoint. It does not migrate POS business records, deploy the new POS, or enable the Supabase/web bridge. Those steps and full end-to-end verification remain. The installer checks local service readiness with the generated CA and never disables TLS validation.

The pairing JSON is private shop connection material and must be transferred directly to the authorized POS, not published in GitHub. Local certificates currently expire in two years and need renewal before expiration. The new service binaries are not code-signed; any Windows security prompts are handled by the operator.
